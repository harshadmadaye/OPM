# opm:brew-idea

Date: 2026-09-16
Status: approved design, awaiting implementation plan

## Goal

One command takes a project brief, or an existing codebase plus a brief, and returns an
improved feature list and a phased plan that several agents have argued over from different
angles. The result is an easy-to-read artifact for humans and a markdown spec the rest of OPM
can pick up (`opm:writing-plans`, `opm:milestone-planning`, `opm:jump-start`).

Nothing in OPM does this today: `opm:brainstorming` is one agent asking one question at a
time, `opm:planner` is one planning agent, and jump-start Phase 1 only fills gaps in a brief.

## Invocation

```
/opm:brew-idea <brief>
```

- Run inside the project directory. The text after the command is the brief.
- If the directory contains source files, the scout maps the code first. If it is empty or
  has no source, the run is brief-only.
- If the brief is shorter than about 15 words, the skill asks one question ("What should it
  do, for whom, on which platform?") and then continues. No other questions before the run.
- No flags in the first version.

Skill frontmatter: `name: brew-idea`, `argument-hint: <project brief>`,
`disable-model-invocation: true`. The description names the trigger phrases ("brew idea",
"brainstorm this project with multiple agents", "improve my project idea").

## The workflow

One Workflow launch per run. Invoking the skill is the opt-in the Workflow tool requires.
Every `agent()` call names its model. Total about 10 agents.

Args passed from the skill:

```
{ projectRoot, brief, hasCode, date }
```

`date` is passed in because scripts cannot call `Date`.

### Phase 1: Scout (1 agent, sonnet)

Reads the brief and, when `hasCode`, the repository (README, package manifests, top-level
layout, routes or screens, data models). Returns a fact sheet:

```
{ summary, users, existingFeatures[], stack, constraints[], gaps[] }
```

### Phase 2: Propose (4 agents, sonnet, parallel)

One agent per angle. Each gets the brief and the fact sheet and returns:

```
{ angle, ideas: [{ id, title, why, impact 1-5, effort 1-5 }], concerns: [{ about, why }], cut: [{ feature, why }] }
```

Angles and their briefs:

| Angle | Argues from |
|---|---|
| product | Who it is for, the problem, which features matter most, what to cut |
| engineering | Stack fit, complexity, cheap vs expensive, risks in the existing code |
| skeptic | Failure modes, security, compliance, what would make the product pointless |
| market | Competitors, prior art, what users expect. Uses WebSearch; anything not verified online is marked `unverified: true` |

Ids are `<angle>-<n>` so the debate and the judge can refer to them.

The barrier after this phase is deliberate: the debate needs all four proposals.

### Phase 3: Debate (4 agents, sonnet, parallel)

Each angle agent gets its own proposal plus the other three and must take a position on every
idea from the others:

```
{ angle, endorse: [id], attack: [{ id, why, severity high|medium|low }], revised: [ideas] }
```

"Attempted" or "maybe" positions are not allowed; every id is endorsed or attacked.

### Phase 4: Judge (1 agent, opus)

Gets the fact sheet, all proposals and all rebuttals. Returns:

```
{
  vision,                       // one line
  features: [{ title, decision keep|improve|add|cut, reason, votes: { for: [angle], against: [angle] }, impact, effort }],
  plan: [{ phase, goal, features: [title], risks: [] }],
  cut: [{ title, reason }],
  openQuestions: [],
  assumptions: [],
  missingAngles: []             // angles whose result was null
}
```

Ranking rule for the judge: impact over effort, ties broken by the number of angles in favour.
A feature attacked with `high` severity by the skeptic needs a stated mitigation or goes to
`cut`.

When the user requests changes, the judge prompt gains a `feedback` block. Because the
scout, propose and debate prompts do not include it, a relaunch with `resumeFromRunId` replays
those three phases from cache and reruns only the judge.

### Return value

`{ facts, proposals, rebuttals, verdict }`. The main thread reads this object only, never
subagent transcripts.

## Output, in the main thread

1. Write `docs/specs/<date>-<slug>-brew.md` from `templates/spec.md`. `slug` is the first
   three meaningful words of the brief in kebab-case, or the directory name when the project
   has code. Sections, in order: vision, feature table (title, decision, impact, effort, who
   was for and against, reason), plan phases, cut list with reasons, open questions,
   assumptions, one short paragraph per angle summarising its position, run metadata (date,
   angles present, unverified market claims).
2. Dispatch one Agent on `opus` to render the markdown to `docs/brew/<slug>.html`: a single
   self-contained page, inline CSS only, readable at 400px, plain language. Sections:
   "In one line", "What we'd build" (feature cards grouped by decision), "Debate highlights"
   (who-said-what cards, one per notable attack or endorsement), "Plan", "Cut and why",
   "Open questions". The renderer invents nothing; every statement comes from the markdown.
3. Publish: if the Artifact tool is available, load `artifact-design` and publish the file
   with a stable title `<name> brew`; republish the same file on every revision. Otherwise
   `open` the file (macOS) or `xdg-open` (Linux).
4. Approval loop with AskUserQuestion: "Approve" or "Request changes" (free text). On
   changes: relaunch the workflow with `resumeFromRunId` and the feedback, rewrite the
   markdown, resume the renderer agent, republish, ask again. Every revision gets its own
   question.
5. On approve: commit the spec and the html (`docs(brew): <slug> brew-idea result`) and
   tell the user the next step: `opm:writing-plans` for a bounded change, `opm:milestone-planning`
   for multi-phase scope, or `opm:jump-start` when the project does not exist yet.

## Error handling

| Situation | Behaviour |
|---|---|
| An angle agent returns null | Log it, continue, judge is told via `missingAngles`, spec and artifact show a "not represented" note |
| Fewer than two proposals | Stop the run, report what happened, no spec, no artifact |
| Market agent has no WebSearch | It says so and marks every claim `unverified`; the artifact shows these as "not checked online" |
| Judge returns null | Stop, report, keep proposals and rebuttals in the returned object so the user can rerun |
| Workflow tool unavailable | The skill stops and tells the user. It does not fake the run with Agent calls |
| Renderer fails | The spec still exists; tell the user and offer to retry the render |

## Models

| Seat | Model |
|---|---|
| scout, 4 proposers, 4 debaters | sonnet |
| judge, renderer | opus |

## Tests

`tests/brew-workflow.test.js`, run with `node --test tests/*.test.js`, same style as
`tests/hooks.test.js`:

1. The script parses when wrapped in an async function with the workflow globals stubbed.
2. Every `agent(` call carries a `model:` option.
3. Every `phase:` label used in an `agent()` call and every `phase()` call matches a title
   in `meta.phases`.
4. `meta` is a pure literal: no `${`, no identifiers outside string values.

Manual: one run on a throwaway brief before the PR is merged, recorded in the PR test plan.

## Out of scope for 0.3.0

- A second debate round or a "deep" mode (judge panel). Add a flag later if results feel shallow.
- Custom angle sets from the command line.
- Feeding brew-idea automatically into jump-start Phase 1.

## Red flags for the skill

| Thought | Reality |
|---|---|
| "I'll run the angles with Agent calls, Workflow is overhead" | The workflow is the contract: deterministic rounds, resume on change requests. Stop if it is missing. |
| "The judge can skip the skeptic, it only says no" | Every attack gets a mitigation or the feature is cut. That is the point. |
| "I'll render the HTML myself" | Dispatch the renderer on opus. The main thread writes the markdown, not SVG. |
| "They approved the last version, this tweak is fine" | Every revision gets its own approval question. |
| "The market agent's claims sound right, no need to flag" | Unverified stays unverified in the artifact. |
